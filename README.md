# CrashRace

「誰が一番早くサーバーを落とせるか」大会(イベント)を開催するためのPaperプラグインです。
参加者が作った負荷装置(レッドストーン回路・エンティティ大量発生装置など)によってサーバーが
クラッシュしかけた瞬間を検知し、原因となった装置・プレイヤーを推定して順位を記録します。

## 主な機能

- **クラッシュ寸前検知**: メインスレッドとは別スレッドで心拍(heartbeat)を監視し、実際に
  サーバーがクラッシュ(Watchdogによる強制終了)する前に「ハング寸前」を検知します。
- **犯人推定**: 直近のブロック・エンティティ設置ログから、負荷が集中しているチャンクと、
  そこで最も活動していたプレイヤーを推定します(ヒューリスティックな推定であり、確定的な
  証拠ではありません)。
- **ランキング表示**: 検知された順に1〜3位を記録し、サイドバースコアボードにリアルタイム表示します。
- **自動ダメージコントロール**: 検知後、原因チャンク周辺のエンティティ掃除・強制リロードに加え、
  直近ログに残っているレッドストーン回路・ピストンなどの危険ブロックを記録済み座標のみ
  ピンポイントで空気化します(チャンク全体のスキャンは行わないため軽量)。エンティティを伴わない
  ピストン連打やレッドストーン点滅によるハングにも対処できます。対象範囲をチャンク単位・
  記録済み座標のみに限定しているため、別途導入する軽量化プラグインと併用できます。
- **adminGUI**: イベント時間・延長・検知感度・自動終了・順位の手動修正をGUIから設定できます。
- **Discord Bot通知**: 大会の開始・検知・終了結果をDiscordチャンネルへ通知できます。検知通知は
  メインスレッドの復帰を待たずに送信されるため、万が一その直後に実際にクラッシュしても
  結果がDiscord側には残ります。

## 動作環境

- Minecraft / Paper **26.2**(2026-06-17リリース、"Chaos Cubed")
- サーバー実行には **Java 25** 以上が必要です

## ビルド方法

```bash
./gradlew build
```

`build/libs/CrashRace-<version>.jar` が生成されます。これをサーバーの `plugins/` フォルダに
配置してください。

GitHub Actions (`.github/workflows/build.yml`) でも push / PR のたびに自動ビルドされ、
Actionsタブの実行結果から Artifact としてダウンロードできます。

## コマンド

権限 `crashrace.admin` (デフォルト: op) が必要です。

| コマンド | 説明 |
|---|---|
| `/crashrace start [分]` | 大会を開始します(分数省略時は設定ファイルのデフォルト値) |
| `/crashrace stop` | 大会を今すぐ終了し、結果を発表します |
| `/crashrace extend [分]` | 制限時間を延長します |
| `/crashrace reset` | ランキング・ログを消去し待機状態に戻します |
| `/crashrace admin` | 管理用GUIを開きます(ゲーム内のみ) |

エイリアス: `/cr`, `/crash`

## adminGUI

`/crashrace admin` で開く管理パネルから、以下をゲーム内で設定・操作できます。

- 大会の開始 / 終了 / リセット
- 時間延長(1クリックで指定分数を追加)
- ハング検知しきい値の調整(±1秒)
- 検知時の自動チャンク掃除のON/OFF
- 3位まで決定した際の自動終了のON/OFF
- 確定した順位の手動取り消し

## 設定ファイル (`config.yml`)

- `event.*`: デフォルト開催時間、延長幅、自動終了、同一プレイヤーの重複順位を許可するか
- `watchdog.*`: ハング検知のしきい値・監視間隔・犯人推定に使う設置ログの時間窓・
  再検知までのクールダウンと回復判定しきい値
- `block-weights`: 犯人推定時にブロック/エンティティ種別ごとに掛ける重み
- `mitigation.*`: 検知後の自動掃除の範囲・挙動(エンティティ掃除・チャンク再読込・
  危険ブロックのピンポイント除去)
- `scoreboard.*`: サイドバー表示の更新間隔・タイトル

`watchdog.hang-threshold-ms` は、サーバー本体のWatchdogタイムアウト(実際にクラッシュする
までの時間)より必ず短く設定してください。先に検知するための値です。

`watchdog.detection-cooldown-ms` と `watchdog.recovery-threshold-ms` は、1回検知した後の
再検知を抑制するための設定です。クールダウン時間が経過し、かつ心拍の遅延が
`recovery-threshold-ms` を下回るまで(=サーバーが実際に落ち着くまで)次の検知は行われません。
これにより、TPS回復中に居合わせただけの別プレイヤーを誤って検知してしまうのを防ぎます。

## Discord Bot通知のセットアップ

1. [Discord Developer Portal](https://discord.com/developers/applications) でアプリケーションを
   作成し、「Bot」タブからBotを追加してトークンを発行する
2. OAuth2 URL Generator で scope に `bot`、permission に `Send Messages` を選び、
   生成されたURLでBotを通知したいサーバーに招待する
3. 通知先チャンネルのIDを取得する(Discordの設定 → 詳細設定 → 開発者モードを有効化した上で、
   チャンネルを右クリック →「IDをコピー」)
4. `config.yml` の `discord.enabled` を `true` にし、`bot-token` と `channel-id` を設定する

Webhook URLではなく、実際にBotアカウントのトークンでDiscord REST APIを直接呼び出す方式です
(ゲートウェイ接続は行わない一方向の通知のみなので、追加ライブラリなしで動作します)。
`bot-token` は秘密情報です。config.ymlをGit等で公開しないよう注意してください。

## 注意事項

- 犯人推定はあくまで「直近の設置ログから最も怪しいチャンク・プレイヤーを割り出す」
  ヒューリスティックです。運営側の目視確認や、必要に応じた `adminGUI` からの手動修正と
  組み合わせて利用してください。
- イベント当日に別途サーバー軽量化プラグインを併用する運用を想定し、本プラグインの自動対処は
  検知した原因チャンク周辺のみに限定しています。
